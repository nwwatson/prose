# Fediverse (ActivityPub)

Federation of the site as a single ActivityPub actor.

## Fediverse (ActivityPub)
Opt-in via `SiteSetting#activitypub_enabled` (Admin → Settings → Fediverse); while off, every ActivityPub route 404s (`ActivityPub::BaseController#require_federation`) and post URLs serve only HTML. The whole site is **one actor** (`@<activitypub_username>@APP_HOST`, a `Person` at `/activitypub/actor`) — there are no per-author actors. Enabling federation the first time generates an RSA-2048 keypair on `SiteSetting` (`activitypub_private_key` is encrypted); it is never rotated automatically because remote servers cache it by key id. Because the actor id is the URL `/activitypub/actor` (not the username), changing the username doesn't break existing follows, but changing `APP_HOST` does.

Everything lives under the `ActivityPub::` namespace (`app/controllers/activity_pub/`, `app/services/activity_pub/` — the directory is `activity_pub` so Rails' default inflection yields `ActivityPub`). **`ActivityPub::Urls` is the single source of every ActivityPub id**: it builds absolute URLs from `AppUrlOptions` (APP_HOST in production), never from the request host, so a URL served by a controller matches the one a background job delivers. It also has `post_for(uri)`, which maps an incoming object id back to a live `Post` (only this host, only `/posts/:slug`). Note `post_url(slug: post.slug, ...)` — passing the record positionally *and* `slug:` puts the record in the `:format` slot (see "Slug Route Helpers" in CLAUDE.md).

Endpoints: `/.well-known/webfinger`, `/activitypub/actor`, `/activitypub/inbox` (also advertised as the shared inbox), `/activitypub/outbox` (20 newest live posts), `/activitypub/followers` and `/following` (counts only — follower identities are never published). `GET /posts/:slug` with an `application/activity+json` or `ld+json` Accept header is routed to `ActivityPub::ObjectsController` by a lambda route constraint (`ActivityPub::Negotiation`) placed before `resources :posts`, so `PostsController` stays HTML-only; `posts/show` adds a `<link rel="alternate" type="application/activity+json">`.

**Signatures**: `ActivityPub::Signature` implements draft-cavage HTTP Signatures (RSA-SHA256 over `(request-target) host date [digest]`, with a SHA-256 `Digest` of the body); the verifier requires those headers to be signed, a Date within 12h (1h future skew), and a matching digest. `ActivityPub::RequestVerifier` resolves the signer via `ActivityPub::ActorFetcher.for_key_id` (cached as a `FediverseActor`, refetched after a day or once on verification failure to pick up key rotation), and the inbox rejects any activity whose `actor` isn't the signer. `ActorFetcher` only accepts a document whose `id` equals the URI requested and whose `publicKey.owner` is that actor. **All outbound HTTP (actor fetches and deliveries) goes through `ActivityPub::HttpClient`**, which sends through `Outbound::Connection` (SSRF guard, IP pinning, no redirects, timeouts — see [webhooks.md](webhooks.md#outbound-http-ssrf-guard)) with bodies capped at `MAX_RESPONSE_BYTES` (1 MB, raising on overflow), signs GETs too (for "authorized fetch" servers), and refuses plain http in production.

**Inbox** (`ActivityPub::InboxProcessor`): `Follow` of our actor → `FediverseActor#follow!` + an `Accept` delivered via `DeliverActivityJob`; `Undo` of a Follow/Like; `Like` of a live post → `FediverseLike` (unique per actor/post; count shown on the admin post dashboard); `Create(Note)` that is public, attributed to the signer, hosted on the signer's domain, and `inReplyTo` a live post (or a top-level fediverse comment) → a `Comment` with `approved: false` and `activitypub_uri` (unique, so redelivery is a no-op), authored by an `Identity` created lazily via `FediverseActor#ensure_identity!` (no handle). Note HTML is converted to plain text by `ActivityPub::CommentBody` — remote HTML is never stored — and a leading mention of our actor is stripped. `Delete` soft-deletes the signer's own comment, or, when the object is the actor itself, removes its follow and likes. An unverifiable `Delete` of an actor by itself (the account is gone, so its key 410s) is acknowledged with 202 and ignored. Replies to replies are dropped (comments are one level deep), and `Update(Note)` is not handled.

**Outbound** (`Post::Federatable`, mirroring `Post::Webhookable`): transition to `published` (including create-as-published) → `FederatePostJob("create")`; transition away from published or destroy → `"delete"` (a Tombstone; the URL is passed in since the post may be gone); a new revision of a published post → `"update"`, **delayed and coalesced** the same way as the `post.updated` webhook (see [posts.md](posts.md#post-revisions-coalesced-updates)). `FederatePostJob` builds the activity (`ActivityPub::Activities` + `ActivityPub::ArticleSerializer`) and enqueues one `DeliverActivityJob` per `FediverseActor.follower_inboxes` (shared inboxes deduplicated). Articles carry full HTML only for `visibility_public?` posts — members-only/paid posts send `seo_description` + a "Read more" link — and rich-text attachments are flattened to plain `<img>`/`<a>` tags with absolute URLs by `RichTextFlattener`. `DeliverActivityJob` retries (polynomial, 5 attempts) on 5xx/429/network errors, drops 4xx, and on `410 Gone` unfollows every follower behind that inbox.

Tests share `ActivityPubTestHelper` (`test/support/activity_pub_helper.rb`, included per test class): `enable_federation!`, `remote_actor`, `remote_key` (generated lazily, once per worker) and `signed_inbox_headers(body)` (signs as that remote actor).

## Absolute URLs
`AppUrlOptions.call` (`app/services/app_url_options.rb`) is the single source of host/port/protocol for URLs built outside a request (webhook payloads, the email logo, and ActivityPub ids via `ActivityPub::Urls.url_options`). It reads `config.action_mailer.default_url_options` and, when that has no protocol, uses `https` if `force_ssl` is on. `production.rb` also sets `protocol:` there so mailer links match. Don't read `default_url_options` anywhere else.
