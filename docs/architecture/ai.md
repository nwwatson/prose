# AI Integration

RubyLLM configuration, AI controllers and streaming responses.

## AI Integration
Uses the **RubyLLM** gem for a unified LLM interface across providers (Claude for text, Gemini/OpenAI for images). API keys are stored with Active Record Encryption on `SiteSetting` — key presence enables a feature, `nil` disables it (no separate toggle). `Ai::Client` (`app/services/ai/client.rb`) is the single place that calls `RubyLLM.configure` — `configure!(settings)` sets all three provider keys, `chat(settings)` configures and returns a `RubyLLM.chat(model: settings.ai_model_name)`, and `paint(prompt, settings)` configures and delegates to `RubyLLM.paint`. `Ai::Configurable#configure_ruby_llm!` and `AiResponseJob`/`GenerateFeaturedImageJob`/`Admin::Ai::FeaturedImagesController` all delegate to it instead of building their own `RubyLLM.configure` block. `configure_ruby_llm!` runs as a `before_action` only on `Admin::Ai::BaseController` (and subclasses) — not on `Admin::BaseController` — so non-AI admin pages don't decrypt AI API keys on every request, and it is declared after `require_ai_configured`, so an unconfigured request is turned away without configuring RubyLLM. AI controllers are nested under `admin/posts/:id/ai/` and streaming responses use Turbo Streams + Solid Cable (`AiResponseJob` broadcasts the reply in batches: every broadcast is a Solid Cable insert on SQLite, so chunks are buffered until `STREAM_FLUSH_INTERVAL` or `STREAM_FLUSH_SIZE` is reached, with a final flush, and HTML-escaped because Turbo inserts them as markup). `Ai::SystemPrompts.for(quick_action, context)` picks the system prompt from its `QUICK_ACTIONS` map, falling back to `chat`. `AiResponseJob` precomputes the latest user message id once before replaying chat history, rather than re-querying it per message in the loop.

Only `Chat` and `Message` are application models (`acts_as_chat` / `acts_as_message`). The model registry, tool calls and usage ledger are RubyLLM's own `ruby_llm_*` tables. `bin/docker-entrypoint` runs `ruby_llm:load_models` on boot so a stored registry can't fall behind the gem. `Ai::Client.paint` passes `provider:` and `assume_model_exists: true` so image generation doesn't depend on the registry listing an id, or resolve it to another provider. When a provider retires a model, replace it in `SiteSetting::AiConfiguration`'s `AI_MODELS`/`IMAGE_MODELS` (first entry = default, also mirrored in the `site_settings` column defaults and `config/initializers/ruby_llm.rb`) and add a data migration that moves saved settings onto the replacement, as `ReplaceRetiredAiModels` does. `RubyLLM::ModelNotFoundError` is not a `RubyLLM::Error`, so rescue both around chat calls.
