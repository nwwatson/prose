# Post Editor

The editor layouts, the shared drawer shell and the editor's Stimulus controllers.

## Post Editor
Uses the `admin_editor` layout. Autosave triggers on a 3-second debounce, serializing `#post_form` FormData. The editor drawer is a tabbed panel (AI + Settings + Versions). Settings fields use `form="post_form"` attribute with event listeners on the settings tab container to trigger autosave.

## Editor Layout Composition
`admin_editor`, `admin_page_editor`, and `newsletter_editor` are thin compositions of shared partials in `app/views/layouts/editor/`: `_head` (`default_title:`, `fonts: true` — newsletter editor passes `fonts: false` to skip `font_stylesheet_tags`/`typography_style_tag`), `_top_bar` (`back_label:`), `_overlay`, `_discard_modal` (`title:`, `message:`; the "Keep editing"/"Discard" button labels are shared under `layouts.editor.*` in the locale files rather than duplicated per layout), and the drawer shell: `_drawer` (`title:`, optional `header_actions:` rendered before the pin button, `data:` merged onto the panel; the block is the tab bar and tab contents) renders the `panel` and `pinIcon` targets and the pin button (title `layouts.editor.pin_panel`), and `_drawer_tab` (`tab:`, `label:`, `active:` for the first paint only) renders a `tabButton` target with its `data-tab`. The post and newsletter editor panels and the page editor layout render these, so change drawer chrome there, never in one editor. `test/system/editor_drawer_test.rb` drives open/tab/pin/Escape in all three. Flash messages across all six layouts (three editors, `admin`, `admin_auth`, and the public `application` layout) render through `layouts/shared/_flash` (`variant: :editor | :admin | :auth | :public`, default `:editor`) so `notice`/`alert` markup lives in one place; the public variant uses the `.flash`/`.flash--notice`/`.flash--alert` BEM classes in `app/assets/tailwind/components/_flash.css`. `Admin::PostsController#load_chat` sets `@chat` and `@chat_messages` (`Chat#conversation_messages`) when `SiteSetting.current.ai_configured?`, rather than the layout performing the lookup/write or the query itself. It runs before `edit`, and from `update` only when a failed non-JSON save re-renders the editor, so autosave does no `chats` query and decrypts no API key; don't make it a `before_action` on `update`.

`editor_drawer_controller.js` owns only drawer chrome — open/close, pin (persisted through `lib/storage.js`), tab switching, Escape, and Cmd/Ctrl+Shift+A. It carries no AI-specific targets or values: it derives whether an AI tab exists from the presence of a `data-tab="ai"` tab button, and `showTab` dispatches `editor-drawer:tab-shown` (with `{ tab }`) **on the panel target**, so controllers mounted inside the panel can react. `ai_chat_controller.js` owns AI chat transport (send, quick actions, clear conversation, Enter-to-send, scroll-to-bottom) and is mounted on the panel root in `admin/posts/_editor_panel.html.erb` only when `ai_available` — the page and newsletter editors render their own panels and never load it. It POSTs to its `messagesUrl` value (clearing goes to `conversationUrl`; quick-action messages come from the translated `prompts` value) via `requestTurboStream` (from `lib/request.js`) rather than building a hidden `<form>`, and reads title/subtitle from the autosave controller's form (`formSelectorValue`) instead of a document-wide `querySelector`.
