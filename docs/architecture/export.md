# Content Export

Markdown and JSON site exports.

## Content Export
Admins export the site from `/admin/exports` (`Admin::ExportsController`, admin role only; linked from the sidebar and `/admin/settings`). `Export` (`format` enum `markdown`/`json` with `validate: true`, so an unknown format is a validation error rather than an `ArgumentError`; `status` enum `pending`/`processing`/`completed`/`failed`; `has_one_attached :file`) keeps only the newest `Export::RETENTION_LIMIT` (10) rows, pruned `after_create_commit`. `ExportJob` calls `Export#exporter` (`Export.exporter_for(format)` → `Exports::MarkdownExporter` / `Exports::JsonExporter`, both in `app/services/exports/`, each `.call` returning a rewound `Tempfile` the caller must `close!`), attaches the result, and `broadcast_replace_to "exports"` with the `admin/exports/_export` partial so the index row updates live. Any exporter error marks the export `failed` with `error_message` instead of raising.

`Exports::MarkdownExporter` writes `posts/<slug>.md`, `pages/<slug>.md` (YAML front matter + body converted with the `reverse_markdown` gem) and `images/<blob id>-<slugified filename>` into a zip via `rubyzip` (streamed with `Zip::OutputStream`; blobs are downloaded in chunks). Rich text attachments are rewritten *before* HTML→Markdown conversion by `RichTextFlattener` (`app/services/rich_text_flattener.rb`, shared with `ActivityPub::ArticleSerializer`): image blobs become `<img>` tags, other blobs become links, and `XPost`/`YouTubeVideo` embeds become plain URL links. Each caller passes only a blob-URL block (`../images/...` here, absolute URLs for ActivityPub) and `wrap:` (a paragraph per attachment here). Add a new embed type there. Filenames are slugified because a space in a Markdown link target breaks the link.

`Exports::JsonExporter` emits `{ format: "prose", version:, site:, authors:, categories:, tags:, posts:, pages:, navigation_items:, subscriber_labels:, subscribers: }` with rich text as HTML (`content_html`). **Site settings use the explicit `SITE_SETTING_ATTRIBUTES` allowlist**, not a denylist, so a newly added API key column is never exported by accident — add a column there only if it's safe to hand out. Password digests and subscriber auth tokens are never included. `.call` streams the document into the tempfile so memory doesn't grow with table size: collections are lazy Enumerators (`each_in_batches` for the id-ordered ones, `in_order` for the small ones with their own sort order) written one record at a time, and the bytes are identical to `JSON.pretty_generate(as_json)`, which a test asserts. Add a new top-level key in `#document`.

Downloads go through `Admin::ExportDownloadsController` (`GET /admin/exports/:id/download`), which uses `ActiveStorage::Streaming#send_blob_stream` behind `require_admin` rather than redirecting to an Active Storage blob URL — those signed URLs don't expire, and a JSON export contains every subscriber email. It's a separate controller because `ActiveStorage::Streaming` includes `ActionController::Live`. `rubyzip` must stay a direct `Gemfile` dependency: it's otherwise only pulled in transitively by `selenium-webdriver` in the test group.
