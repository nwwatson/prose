# Internationalization

Site locale, date/time formatting and the translation rules enforced by tests.

## Internationalization (i18n)
Site-wide locale configured via `SiteSetting.locale` (default: `"en"`). The `SiteSetting::Localization` concern defines `SUPPORTED_LOCALES` and validates the locale value. `ApplicationController` sets `I18n.locale` from the site setting on every request. Mail and jobs run under it too: `ApplicationMailer` has an `around_action` and `ApplicationJob` an `around_perform`, both `I18n.with_locale(SiteSetting.current.locale)`, so new mailers and jobs must inherit from them. The job callback overrides the enqueue-time locale Active Job restores (English for recurring tasks and API requests); `retry_on`/`discard_on` blocks run outside it. `ActionController::API` controllers (REST, MCP, ActivityPub) set no locale and answer in English. All UI strings live in `config/locales/en.yml` and `config/locales/es.yml`. To add a new locale: add the language code to `SUPPORTED_LOCALES` in `app/models/site_setting/localization.rb`, add it to `config.i18n.available_locales` in `config/application.rb`, and create the corresponding YAML file in `config/locales/`.

Dates and times are rendered via `l(value, format: :short|:long|:with_time)`, never `strftime`, so they follow the site locale. Named formats live under `date.formats`/`time.formats` in each locale file — `date.formats` (`short`, `long`) for date-only values and `time.formats` (`short`, `long`, `with_time`) for values that include a time of day. Because there's no `rails-i18n` gem, each locale file also defines its own `date.month_names`/`abbr_month_names`/`day_names`/`abbr_day_names` and `time.am`/`pm` — without these, `%B`/`%A`/`%p` in a format string raise `I18n::MissingTranslationData` for any locale ActiveSupport doesn't ship a default for (i.e. anything but English). **`l` dispatches on the argument's class**: a `Date` uses `date.formats`, while a `Time`/`ActiveSupport::TimeWithZone` uses `time.formats` — so a date-only display of a timestamp column (`created_at`, `published_at`, etc.) must call `l(value.to_date, format: :short)`, not `l(value, format: :short)`, or it silently pulls from `time.formats` instead. `ApplicationHelper#published_on(record, **html_options)` wraps this for the `<time datetime="...">` tag used by post card partials (`posts/_post`, `posts/_related_posts`, `posts/show`, `admin/posts/_preview`).

No user-facing string is hard-coded in a view or controller. `test/models/locale_files_test.rb` fails unless `en.yml` and `es.yml` have identical key sets (which is why `en.yml` repeats ActionView's `datetime.distance_in_words` defaults). Relative times go through `ApplicationHelper#time_ago(time, never:)` (`shared.time_ago` wraps the phrase, so word order is per locale), never `time_ago_in_words` plus an "ago" suffix. Enum values shown to users go through `AdminHelper#status_label(record, status = record.status)` (`admin.statuses.<model>.<status>`) or `interval_label`, not `capitalize`/`titleize`; email template, font and provider names through the `email_*` helpers rather than the English names in the model constants. Form error headings are count-pluralized keys (`errors_prevented` with `one`/`other`). Stimulus controllers that write text get it from `data-*-value` attributes rendered with `t()` (`StimulusLabelsHelper` writes the set for `autosave` and `code-highlight`, which several views mount), and take endpoints as URL values built with route helpers; where a toggle swaps icon and label (`post_preview`), the view renders both and the controller flips `hidden`. Page titles use `page_title(t(...))`.
Active Record translations (`activerecord.models`/`attributes`/`errors`, `helpers.submit`, `errors.messages`, `support.array`) cover `f.label`/`f.submit` without explicit text and validation messages. Without `rails-i18n`, both locale files carry every default Active Model/Active Record error message (`test/models/active_record_translations_test.rb` fails when Rails adds one). A new model or user-facing attribute needs its `activerecord` entries. Custom validation messages are symbols (`errors.add(:url, :http_url)`, `message: :url_safe_slug`) defined under `errors.messages`, never English strings; per-attribute wording goes under `activerecord.errors.models.<model>.attributes.<attribute>.<key>`. `helpers.label.email`/`password` translate the sign-in form, which has no model.
