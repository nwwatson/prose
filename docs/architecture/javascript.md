# JavaScript

Importmap entry points, Stimulus controllers and the shared JS modules.

## JavaScript Entry Points
There are two importmap entry points. `application` (`app/javascript/application.js`: Turbo plus `controllers/index.js`, which eager-loads `app/javascript/controllers/`) is all the public layout loads (`javascript_importmap_tags`). `admin` (`app/javascript/admin/index.js`) imports `application`, then `lexxy`, then eager-loads `app/javascript/admin/controllers/`; `layouts/admin`, `layouts/admin_auth` and `layouts/editor/_head` load it with `javascript_importmap_tags "admin"`. **Put a controller in `app/javascript/controllers/` only if a public view uses it** (it then works on admin pages too); admin-only controllers go in `app/javascript/admin/controllers/`, and admin-only helpers in `app/javascript/admin/lib/` (imported as `admin/lib/<name>`). Identifiers don't change: stimulus-loading strips the `admin/controllers/` prefix, so `admin/controllers/ai_chat_controller.js` registers as `ai-chat`, not `admin--ai-chat`. A public view that starts using an admin controller must move it to `controllers/`, or it silently won't connect for readers.

`config/importmap.rb` scopes preloads by entry point: `pin_all_from "app/javascript/admin", preload: "admin"`, `lexxy` and `@rails/activestorage` (Lexxy imports it on demand for uploads) are `preload: "admin"`, so public pages emit no `modulepreload` for them; `@rails/actioncable` is `preload: false` because `turbo.min.js` bundles its own Action Cable consumer and nothing imports the pin. Every pin still appears in the import map JSON on every page, which is what lets a Turbo visit from a public page into an admin page run the new `import "admin"` script and register the admin controllers without a full reload. `test/integration/javascript_entry_points_test.rb` asserts the public post page preloads no admin modules.

## Shared JS Modules
`app/javascript/lib/` holds framework-agnostic helpers shared across Stimulus controllers (pinned via `pin_all_from "app/javascript/lib", under: "lib"` in `config/importmap.rb`, imported as `lib/<name>`). Helpers only admin controllers use live in `app/javascript/admin/lib/` instead (`click_outside`, `listbox`, `svg_chart`, `action_text`, `transition`, `webauthn`, imported as `admin/lib/<name>`), so public pages don't preload them.

`lib/clipboard.js#copyText(text)` is the single clipboard implementation (`navigator.clipboard`, falling back to `execCommand`); it resolves to `true`/`false` and never throws. `share` and `code_highlight` use it.

`admin/lib/webauthn.js` holds the passkey encoding: `decodeOptions(options)` (turns the server's base64url `challenge`, `user.id` and credential ids into ArrayBuffers for `navigator.credentials.create`/`get`), `serializeCredential(credential)` (the JSON the server verifies, for both attestation and assertion responses) and the two base64url helpers. `test/system/passkeys_test.rb` runs both ceremonies against Chrome's virtual authenticator.

`lib/request.js` centralizes the CSRF-token meta lookup and the three fetch idioms used throughout the app: `request(url, opts)` (sets `X-CSRF-Token`, JSON-encodes a plain object body, form-encodes a `URLSearchParams` body, passes `FormData` through untouched, and forwards an abort `signal`), `requestJSON(url, opts)` (parses the JSON response and throws with `data.error` when the response isn't ok), and `requestTurboStream(url, opts)` (sets the Turbo Stream `Accept` header and renders the response via `Turbo.renderStreamMessage`). Controllers that POST or fetch should use these helpers instead of duplicating the CSRF meta-tag lookup.

`lib/dom.js` holds `escapeHtml(str)` (the single HTML-escaping implementation in the app — `lib/markdown.js`, `custom_select` and anything else interpolating untrusted text into a template literal import it rather than rolling their own) and `capitalize(str)` (used to build Stimulus `has<Name>Target` property names in `email_branding_preview`).

`admin/lib/click_outside.js` exposes `useClickOutside(controller, { onClickOutside })`, which returns `{ observe, unobserve }` instead of registering immediately. Dropdown controllers call `observe()` in `open()` and `unobserve()` in `close()` and `disconnect()`, so a `document` click listener only exists while a dropdown is actually open.

`admin/lib/listbox.js` provides `ListboxNavigator`, the shared Up/Down/Home/End/Enter/Space/Escape (plus optional type-ahead) handling for `tag_select` and `custom_select`. It owns only the highlighted index; everything visual or app-specific is injected — `getItems`, `highlight(item, on)`, `onSelect(item)`, `onEscape(event)`, `clearHighlight`, `isOpen`/`onOpenRequest`, `getItemText`, and the `typeAhead`/`homeEnd`/`selectOnSpace` flags. `handleKeydown(event)` returns whether it handled the key, so callers can fall through to their own (e.g. `tag_select`'s Backspace-removes-last-pill). **Both selects bind keydown to `this.element`, not `document`, and call `stopPropagation()` on Escape** — that is what lets the first Escape close an open dropdown and only the next one reach `editor_drawer`'s document-level handler and close the drawer. Do not move either listener back to `document`; the drawer no longer probes for open dropdowns in the DOM.

`app/views/shared/_tag_select.html.erb` keeps the pill and option markup in `<template>` elements (`pillTemplate`, `optionTemplate`) that `tag_select_controller` clones, and `shared/_custom_select` does the same with an `optionTemplate` per `<option>` (swatch set through `style`, removed when there's no color), so neither controller builds HTML strings. **Both selects keep "selected" in each option's `aria-selected`**, styled with Tailwind `aria-selected:` / `group-aria-selected:` variants (the checkmark is always rendered and shown by `group-aria-selected:flex`); never test or query a colour class for selection state.

`admin/lib/transition.js` is the single show/hide-with-transition implementation for dropdowns, backdrops and overlays: `fadeIn(el, { off, on })` removes `hidden`, forces a reflow and swaps the `off` classes (default `opacity-0`) for `on`; `fadeOut(el, { off, on, waitFor })` swaps them back and adds `hidden` once `waitFor`'s transition ends (with a timer fallback, since `transitionend` never fires on an unrendered element); `hide(el)` does it at once. Every call first cancels the element's pending hide, so reopening mid-transition can't be undone by a stale `transitionend` listener. `custom_select`, `editor_drawer`'s overlay and `admin_sidebar`'s backdrop use it; don't hand-roll `transitionend` listeners.

`admin/controllers/modal_controller.js` is the generic backdrop + dialog (`backdrop`/`dialog` targets, `open`/`close` actions): body scroll lock (released in `disconnect` too), focus moved into the dialog (`tabindex="-1"`) and returned on close, and Escape handled on `this.element` with `stopPropagation()`, so the first Escape closes the modal and only the next reaches the editor drawer. It dispatches `modal:opened`. Other controllers open it by event instead of owning its markup: `autosave#handleBack` dispatches `autosave:discard-requested`, which `layouts/editor/_discard_modal` routes to `modal#open` (`@window`); the AI featured-image dialog mounts `ai-image-modal modal` on one element, and `modal:opened` triggers `ai-image-modal#suggestPrompt`.

`admin/lib/svg_chart.js` is the shared renderer for all hand-rolled SVG charts (no external charting library) — `svgEl(name, attrs, text)` builds namespaced SVG elements, `renderBarChart(container, entries, opts)` draws gridlines/bars/x-labels for `growth_chart` and `traffic_chart` (which differ only in `minBarWidth`, `labelInterval`, and label formatter — `formatMonthLabel`/`formatDayLabel`), and `renderSparkline(container, values, opts)` draws the dashboard's line+area sparkline (`chart_controller`). Chart colours are Tailwind `fill-*`/`stroke-*` classes on the SVG elements (not hex attributes), and `range_slider`'s gradient uses `var(--color-*)`. All three controllers render into a persistent container element via `container.replaceChildren(...)`, so redrawing (e.g. on data change) doesn't destroy the target. The growth chart's Monthly/Cumulative toggle uses Stimulus `static classes` (`data-growth-chart-active-class` / `-inactive-class`) with `classList.add/remove` rather than string replacement on `className`.

`lib/timers.js` keeps Stimulus timers tied to the controller lifecycle — an untracked `setTimeout` survives `disconnect()` and keeps firing against a detached controller after a Turbo navigation. `debounce(fn, ms)` returns a wrapped function with a `.cancel()` method (used by `handle_check`); `useTimeouts()` returns `{ set, clear, clearAll }` that tracks every timeout id so `disconnect()` can `clearAll()` (used by `autosave`, `custom_select`, `share`, `toc` and `code_highlight`). `autosave` also keeps a `connected` flag so a response landing after disconnect can't queue a new retry, which is what made a failed save loop forever after navigating away.

`lib/storage.js` exports a `storage` object (`get`/`set`/`remove`/`getBoolean`) wrapping `localStorage` in try/catch — the API throws outright in private-browsing/blocked-site-data configurations, and an unguarded read inside `connect()` aborts the whole controller. `editor_drawer` and `theme_toggle` go through it; the inline theme boot script in `layouts/application.html.erb` has its own try/catch since it runs before the module graph loads. The `theme` key name is shared between that script and `theme_toggle`, so don't rename it.
