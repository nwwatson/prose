# Paid Memberships (Stripe)

Membership tiers, Stripe sync and content gating.

## Paid Memberships (Stripe)
Prose supports Ghost-style paid memberships with Stripe integration. Feature is gated — UI only appears when Stripe keys are configured in `SiteSetting`. Direct Stripe API keys (not Stripe Connect), stored encrypted like AI keys. 3-level post visibility: `public` (default), `members_only` (free sign-in), `paid_only` (subscription required). `PaymentService::Stripe` handles checkout sessions, billing portal, subscriptions, and webhook event construction — see [email.md](email.md#email--payment-provider-adapters). `StripeWebhookJob` processes checkout completions, subscription updates/deletions, and payment failures (idempotent) — it's a thin dispatcher that delegates status mapping and attribute syncing to `Membership::StripeSyncable`. `SyncStripeSubscriptionJob` runs daily to keep membership status in sync, also via `StripeSyncable`. Stripe keys are entered on `/admin/settings`; admin controllers at `/admin/membership_tiers`, `/admin/memberships`, `/admin/revenue`. Public pricing page at `/memberships`. Content gating in `posts/show` — `PostsController` sets `@can_view` via `MembershipAccess` concern. Query objects: `RevenueQuery` (MRR, ARR, churn) and `MembershipGrowthQuery` (new/canceled/net by month).

`PaymentGating` (`app/controllers/concerns/payment_gating.rb`), included on `ApplicationController`, is the single source of Stripe-configuration gating: `helper_method :payments_configured?` (memoized per request via a `defined?(@payments_configured)` guard, mirroring `SiteHelper#default_og_image_url`) replaces direct `PaymentService.configured?` calls in views (`posts/_paywall`, `layouts/_admin_sidebar_content`, `admin/membership_tiers/_tier_row`/`_tier_card`), and `require_payments_configured(redirect_to: root_path, alert: nil)` is a `before_action` that redirects when Stripe isn't configured — `MembershipsController` uses the default (silent redirect to `root_path`), while `Admin::RevenueController` overrides it to call `super(redirect_to: admin_root_path, alert: t("flash.payments.not_configured"))`. `Admin::MembershipTiersController` and `Admin::MembershipsController` are deliberately left ungated — tiers must be manageable before their first Stripe sync, and comp memberships (`Membership.grant_complimentary!`) don't require Stripe at all.

`Membership::StripeSyncable` centralizes the Stripe→Membership mapping shared by both jobs: `Membership.status_from_stripe(stripe_status)` maps a Stripe subscription status string to the `status` enum (unknown statuses fall back to `:incomplete`); `#sync_from_stripe!(subscription)` accepts either a `Stripe::Subscription` object or a string-keyed Hash (webhook payload) and updates `status`/`current_period_start`/`current_period_end`/`canceled_at` — missing period fields leave the stored value untouched, while `canceled_at` always reflects the given value (including clearing it back to `nil`) since Stripe always sends that field on a full subscription object; `Membership.activate_from_checkout!(session_data, subscription)` handles `checkout.session.completed` — looks up the subscriber by email and the tier by Stripe price ID, then `find_or_create_by!`s the membership (idempotent against duplicate webhook delivery) before calling `sync_from_stripe!`.

`Membership.grant_complimentary!(subscriber:, membership_tier:)` creates a Stripe-free active membership (100-year period) for admin-granted comps. It's invoked from the subscriber show page via `POST /admin/subscribers/:subscriber_id/memberships/comp` (`admin_subscriber_comp_membership_path`, routed to `Admin::MembershipsController#comp`) rather than a member route on `admin/memberships`, since granting a comp creates a new membership and doesn't operate on an existing one.

`MembershipTier::Syncable` runs Stripe product/price creation `after_commit` (not `after_save`) via `SyncMembershipTierJob`, so the HTTP round-trip to Stripe never holds SQLite's single writer lock open during the save transaction. The admin tiers index (`app/views/admin/membership_tiers/index.html.erb`) shows a "Syncing…" badge on any tier missing a `stripe_price_id` and subscribes to a `"membership_tiers"` Turbo Stream; `SyncMembershipTierJob` broadcasts a `broadcast_replace_to` for both the tier's mobile card and desktop row partials once the sync completes, so the badge clears without a page reload.
