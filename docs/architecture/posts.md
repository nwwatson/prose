# Posts

Post content and search indexing, post cards, the post page, versioning, status transitions, coalesced revisions and the RSS feed.

## Post Content & Search Indexing
`Post#body_plain` is the canonical plain-text source for a post's content — `Post#excerpt(length)` truncates it and is used by `seo_description`, the featured-post teaser, and the gated-content teaser. Never re-derive plain text from `content.to_plain_text` outside of `Post::Searchable#update_body_plain`; that callback only recomputes `body_plain` when `content` actually changed (`before_save :update_body_plain, if: -> { new_record? || content.changed? }`), so a settings-only save (autosave, love counter, status toggle) skips the Nokogiri parse. `calculate_reading_time` is similarly guarded with `will_save_change_to_body_plain?`. The `posts_fts_update` SQLite trigger has a `WHEN` clause so the FTS5 row is only deleted/reinserted when `title`, `subtitle`, or `body_plain` actually changed. Run `rake posts:backfill_body_plain` to populate `body_plain` for posts created before the column existed.

The FTS5 body snippets shown on public search results quote post text, so `PostsController#index` keeps a snippet only for posts the reader can view (`can_view_post?`); don't pass `Post.search_with_snippets` results to a view unfiltered. The snippet is part of the post-card cache key (see Post Cards below), which is what keeps a member's card from being served to anonymous readers.

## Post Cards & Listing Pagination
Post cards (`posts/_post`) are only rendered through `PostCardsHelper#render_post_cards(posts, snippets: {}, **options)`, never with `render "posts/post"` in a loop: it renders a collection with a `cached:` lambda, so a listing's cards are fetched with one `read_multi` (one Solid Cache query) instead of a read per card, and the partial has no `cache` block of its own. Collection caching keys **only** on the lambda's value, not on the locals, so `post_card_cache_key` is built from `PostCardsHelper::POST_CARD_OPTIONS` (every display option and its default) plus the post, author identity, category, search `body_snippet` and `I18n.locale`; `render_post_cards` rejects an option missing from that list. Add a new card option there, never as a bare partial local, or two different cards will share one cache entry. The partial's strict locals have no defaults for the same reason. `snippets` maps post id → search result; pass only what `PostsController#viewable_snippets` allowed.

The home page, category, tag and signed-in `/reading-list` pages are paginated with `Paginatable#paginate` (10 per page) and infinite scroll: `posts/_post_page` (`posts:`, `page:`, `next_page:`, `next_page_path:`, optional `snippets:`/`card:` options) renders one `posts_page_<n>` turbo frame plus a lazy frame for the next page. `Paginatable#post_page_frame_request?` detects that frame request; category, tag and reading-list actions answer it with `render layout: false` of the full template (Turbo keeps only the matching frame), while `PostsController#index` renders the `_post_page` partial directly to skip the featured hero. Author pages keep their "Load more" link. The anonymous reading list (`ReadingListPostsController`, up to `ReadingListItem::MAX_ITEMS` ids) is not paginated. The sitemap selects only `slug`/`updated_at`.

## Post Page
`posts/show` renders the Action Text body once (`@post.content.to_s`), builds a `TocExtractor` from that string only when `show_toc`, and renders either result through `posts/_body`; don't call `@post.content` again there. The hero image overrides the helper's `loading: "lazy"` with `eager`/`fetchpriority: "high"`. `previous_post`/`next_post` select only `id`, `slug` and `title`, so widen the select before reading anything else from them. `test/integration/hot_request_paths_test.rb` holds the query and render counts for this page and for autosave.

## Post Versioning
`PostVersion` stores full snapshots (title, subtitle, content HTML, body plain text) on each save. Auto-versioning triggers on update with a 5-minute cooldown (`Post::Versionable`). Manual "Save version" button in the editor drawer's Versions tab. Diff view uses the `diffy` gem for plain-text comparison. "Restore" replaces the post's current content. Max 50 versions per post, pruned inline on version creation. Admin CRUD at `/admin/posts/:id/post_versions`.

## Post Status Transitions
`Post::Notifiable`, `Post::Webhookable` and `Post::Federatable` all react to status changes from `after_commit on: [:create, :update]`, using the shared predicates in `Post::StatusTransitions`: `became_published?`, `became_scheduled?`, `left_published?` (the status before the last save was published) and `edited_while_published?` (no status change, published, and `revised?`). On create the "before" status is the column default (draft), so creating a post already published behaves exactly like publishing a draft: one email, one `post.published` webhook, one fediverse `Create`. Use these predicates rather than re-deriving transitions from `saved_change_to_status?` in a new concern.

## Post Revisions (Coalesced Updates)
`Post::Revisable` stamps `posts.revised_at` in a `before_save` whenever a save changes something readers and integrations see: `REVISED_ATTRIBUTES` (title, subtitle, slug, body_plain, visibility, published_at, meta_description). Settings-only saves (featured, show_toc, category) and counter bumps move `updated_at` but not `revised_at`. It's included right after `Post::Searchable` so a content change has already reached `body_plain`. `Post::Webhookable` and `Post::Federatable` enqueue their "updated" notification (`PostUpdatedWebhookJob`, `FederatePostJob("update")`) only when `revised?`, delayed by `Post::Revisable::UPDATE_DELAY` (2 minutes) and carrying `revised_at.to_f`; the job skips itself when `post.revised_since?(revision)`, so autosave every 3 seconds yields one notification per burst. Coalescing on `revised_at` rather than `updated_at` is deliberate: a settings-only save after an edit would otherwise make the edit's job skip with no newer job queued.

## RSS Feed
`/feed` is anonymous, so `feeds/index.xml.builder` puts the full body in `content:encoded` only for `visibility_public?` posts; members-only and paid posts get `seo_description` plus a "read the full post" link, matching `ActivityPub::ArticleSerializer`. Never emit `post.content` to an unauthenticated surface without that check.
