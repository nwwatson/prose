# Reading List

Bookmarks for anonymous and signed-in readers.

## Reading List (Bookmarks)
Readers save posts for later with the bookmark icon rendered by `ReadingListHelper#bookmark_button` in every post card's meta row (`posts/_post`) and on `posts/show`, and view them at `/reading-list` (`ReadingListController#show`, also linked from the masthead icon group `.masthead__actions`; `reading-list` is a reserved `Page` slug). `ReadingListItem` belongs to `Identity` (like `Love`/`Comment`), so staff users signed into the public site get a list too.

**The button markup is reader-agnostic** — it lives inside the fragment-cached `posts/_post` partial, so it renders `hidden` with `aria-pressed="false"` and `bookmark_controller.js` reveals it and applies the saved state client-side. Never render per-reader state into it. `lib/reading_list.js` is the single source of truth for every button: anonymous readers' ids live in localStorage (`reading_list` key, JSON array, newest first); signed-in readers' ids come from `<meta name="reading-list" content="account" data-post-ids=... data-items-url=... data-import-url=...>` emitted by `ReadingListHelper#reading_list_meta_tag` in the public layout (anonymous: `content="local"`). Account state is held in module memory and only re-seeded from the meta when its `data-key` changes (sign-in/out), because a Turbo restoration visit restores a head snapshot that may predate the reader's last toggle; toggles also write back to the meta so later snapshots are current. Every change dispatches `reading-list:changed` on `window`, which each button listens for (plus `storage` for other tabs).

Signed-in toggles are optimistic and go through the JSON endpoints `POST /reading-list/items` / `DELETE /reading-list/items/:post_id` (`ReadingListItemsController`); the first page a reader loads signed in POSTs any localStorage ids to `/reading-list/import` (`ReadingListImportsController` → `Identity#import_reading_list!`, which skips non-live/duplicate ids and respects the cap) and then clears localStorage. The import is a single `insert_all` (it bypasses `ReadingListItem`'s validations and callbacks, so it applies those rules itself, inside one transaction) with `created_at` staggered by a microsecond to keep the browser's newest-first order. All three return `{ post_ids: [...] }` and share `ReadingListJson` (401 JSON instead of a redirect when signed out). Anonymous readers' `/reading-list` page renders a turbo frame whose `src` `reading_list_controller.js` points at `GET /reading-list/posts?ids=...` (`ReadingListPostsController`, live posts only, in the given order) plus a subscribe prompt to sync across devices. Only live posts are ever listed; saved drafts/unpublished posts stay in the table but are filtered out by `Post.live`.
